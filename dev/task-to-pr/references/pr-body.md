# PR 本文に加える欄

プロジェクトの PR テンプレートの概要の後に加える。テンプレートに検証やテストの欄があれば、そこに書く。

- 最初に読むのはレビュアー。完了要件を満たしたかが表だけで分かるようにする
- RED と GREEN の列には、記録先の `logs/` に保存した出力から結果の行をそのまま書く
- 元のチケットがあれば、概要の欄にリンクを書く。GitHub の issue なら、テンプレートの書き方（`closes #{番号}` など）に従う
- 手元にしかないファイルのパスは書かない
- 中身のない節は省く

```markdown
## テスト結果

RED: {RED の SHA の先頭 7 桁} / GREEN: {head の SHA の先頭 7 桁}

| 完了要件 | テスト | RED（実装前） | GREEN（実装後） |
|---|---|---|---|
| [R1] {要件} | `{ファイル}:{行}` | ❌ {失敗の要点} | ✅ |
| [R2] {要件} | 代わりの確認: {方法} | - | ✅ |

<details><summary>実行したコマンド</summary>

| コマンド | 結果 |
|---|---|
| `{テスト一式}` | ✅ {件数} passed |
| `{lint}` | ✅ |

</details>

## ブラウザでの確認

| 完了要件 | 操作 | 結果 |
|---|---|---|
| [R1] | {操作} | ✅ / ❌ |

スクショ付きの QA シートは作業者の手元にある（`qa-sheet.xlsx`）。

## レビューで直したこと

- {指摘} → {どう直したか}

## 残した注意点

- 既存の失敗: `{コマンド}` はベース（{SHA}）でも同じく失敗する
- 見送ったレビュー指摘（任意）: {指摘}
```
