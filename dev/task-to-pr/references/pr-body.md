# PR 本文に加える欄

プロジェクトの PR テンプレートに検証やテストの欄（「確認したこと」など）があれば、その欄の中に書く。無ければ概要の後に加える。

- 最初に読むのはレビュアー。完了要件を満たしたかが表だけで分かるようにする
- RED と GREEN の列には、記録先の `logs/` に保存した出力から、テストごとの結果の行をそのまま書く
- ベースで通る [Rn] テストの RED 列は、`logs/mutation-*.txt` があるものだけ「✅（違反を入れると落ちることを確認）」と書く。無ければ「確認なし」と書く
- 代わりの確認は `logs/alt-R{n}.txt` か `logs/alt-R{n}-visual.md` があるものだけ ✅ にする
- 環境に依存するテスト（計画が挙げたもの）と、環境に依存する既存の失敗は、「残した注意点」に名前で全部書く
- 元のチケットがあれば、概要の欄にリンクを書く。GitHub の issue なら、テンプレートの書き方（`closes #{番号}` など）に従う
- 手元にしかないファイルは、ファイル名だけを書き、フルパスは書かない
- 中身のない節は省く

```markdown
## テスト結果

RED: {RED の SHA の先頭 7 桁} / GREEN: {head の SHA の先頭 7 桁}

| 完了要件 | テスト | RED（実装前） | GREEN（実装後） |
|---|---|---|---|
| [R1] {要件} | `{ファイル}:{行}` | ❌ {失敗の要点} | ✅ |
| [R2] {要件} | 代わりの確認: {方法} | - | ✅ |

<details><summary>実行したコマンド</summary>

| コマンド | 結果 |
|---|---|
| `{テスト一式}` | ✅ {件数} passed |
| `{lint}` | ✅ |

</details>

## ブラウザでの確認

| 完了要件 | 操作 | 結果 | スクショ |
|---|---|---|---|
| [R1] | {操作} | ✅ / ❌ | `after/R1.png`（変更前 `before/R1.png`） |

## レビューで直したこと

- {指摘} → {どう直したか}

## 残した注意点

- 既存の失敗: `{コマンド}` はベース（{SHA}）でも同じく失敗する
- 見送ったレビュー指摘（任意）: {指摘}
```
