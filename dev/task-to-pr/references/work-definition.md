# 作業定義

ヒアリングで埋め、記録先の `work-definition.md` に保存する。以降のエージェントには、要件としてこのファイルだけを渡す。

| 項目 | 内容 | 埋まらないとき |
|---|---|---|
| 目的・背景 | なぜこの変更が必要か、誰が困っているか | 質問する |
| 完了要件 | 満たせば完了と言える条件。1 行 1 条件で、テストや操作で確かめられる文にする | 確かめられる文になるまで聞き返す |
| 参考情報 | 元のチケット、仕様書、関連 PR などのリンク | 空欄でよい |

対象はカレントのリポジトリの既定ブランチ。

完了要件の例:

- ✅ 「メールアドレスが空のまま送信すると、フォームの下に『メールアドレスを入力してください』と表示され、保存されない」
- ❌ 「バリデーションをちゃんとする」（何をもって完了か確かめられない）

```markdown
# {タイトル}

## 目的・背景

## 完了要件

- [R1] …
- [R2] …

## 参考情報
```

完了要件の `[R1]` などの番号は、計画・テスト・レビュー・QA・PR 本文で同じものを使う。
