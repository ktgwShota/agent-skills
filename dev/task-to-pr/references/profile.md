# プロファイル

プロジェクトごとの違いをまとめたもの。初回にリポジトリを調べて `{HOME}/profiles/{owner}/{repo}.md` に作り、2 回目以降はそれを読む。

## 調べる場所

README・CLAUDE.md・AGENTS.md・`.claude/`（rules と skills）・`.cursor/rules`、パッケージの定義ファイル（`package.json`・`pyproject.toml`・`go.mod`・`Gemfile` など）、CI の設定（`.github/workflows` など）、PR テンプレート、`git log` のコミットメッセージ。

- コマンドは CI で実際に実行しているものを優先する。CI が設定している環境変数（`TZ` など）も書く
- 資料同士で規則が食い違うときは、両方と出典を書き、承認のときにユーザーに聞く
- 調べても分からない項目は「不明」と書き、承認のときに聞く
- 実行中にプロファイルの誤りに気づいたら直し、報告で伝える

## 形式

```markdown
# {owner}/{repo}

## リポジトリ

- 既定ブランチ:
- ブランチ名の規則:（例: `feat/{slug}`。出典）
- コミットメッセージの規則:（形式・言語・署名を付けるか。出典）
- PR テンプレート:（パス）
- PR のタイトル・ラベルの規則:（出典）
- issue の読み方: `gh api repos/{owner}/{repo}/issues/{番号}`

## パッケージ

### {パッケージ名}（{ルートからのパス}）

- 依存ファイル:（例: `package.json`, `package-lock.json`）
- 依存の追加: `{コマンド}`
- worktree の準備: `{コマンド}`（例: `npm ci`）
- テスト（ファイル指定）: `{コマンド} {ファイル}`
- テスト（一式）: `{コマンド}`
- lint: `{コマンド}`
- 型チェック: `{コマンド}`
- 環境変数:（CI に合わせるもの。例: `TZ=Asia/Tokyo`）
- テストファイル:（glob。例: `tests/**/*.test.ts`）
- テスト補助ファイル:（factory・fixture・共通 setup の glob）
- 開発サーバー:（画面がある場合。起動コマンドと URL）

## 実行環境

（テストに必要なランタイム・DB・Docker など。サンドボックスで入れたもの）

## 規則の食い違い

（資料同士で食い違った規則と、ユーザーが選んだもの）

## 出典

（各項目を確かめたファイル）
```
