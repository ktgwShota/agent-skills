# レビュー返信の型

## 返信の構成

1. **結論**: 以下のいずれかの対応方針を書く
   - 例（対応する）: 「ご指摘の通りでしたので修正しました」
   - 例（対応しない）: 「〜のため、今回は対応なしで進めさせてください」
   - 例（別issue）: 「本PRのスコープ外のため、別issueで対応します」
   - 例（確認中）: 「〜に確認中です。結果が出たら改めて返信します」
2. **補足**: 分類に応じて添える
   - 対応する: 修正コミットの SHA
   - 対応しない: 判断の理由
   - 別issue: 作成した issue のリンク
   - 確認中: 確認先と、返信できる見込み

## 書き方のルール

- **反対意見は理由を添えて率直に書き、相談ベースで着地させる**
  - 例: 「その対応は不要です」ではなく「〜のため問題ないと考えているのですが、いかがでしょうか？」

## 投稿フロー

1. 文面をチャットに提示し、ユーザーの OK を得てから投稿する
2. 該当コメントのスレッドへの返信として投稿する:

   ```bash
   gh api repos/{owner}/{repo}/pulls/{pr}/comments/{comment_id}/replies -f body='...'
   ```

   - comment_id はコメント URL 末尾 `discussion_r{id}` の数字
3. 投稿後は返信 URL を報告する
4. 修正は新規投稿ではなく `gh api -X PATCH .../pulls/comments/{id}` で編集する
