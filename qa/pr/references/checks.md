# 変更の種類ごとの確認方法

PR が複数の種類にまたがるときは、該当するものをすべて選ぶ。どの種類でも、リポジトリにあるテスト・型チェック・lint は実行する。

## 変更の目的ごと

- **バグ修正**: 変更前のコードで不具合を再現し、変更後に再現しないことを確かめる
- **機能追加・仕様変更**: 受け入れ要件を 1 つずつ確かめる。要件の境界値と異常系も確かめる
- **リファクタリング**: 変更前後で振る舞いが変わらないことを確かめる
- **依存の更新**: 更新したものを使っている箇所の動作と、更新の目的（脆弱性の解消など）が達成されたかを確かめる

## 変更の対象ごと

### Web フロントエンド

- 対象の画面幅・ブラウザで操作し、動画とスクショを撮る
- 通信（URL・メソッド・ステータス・送信内容）とコンソールを記録する
- ビルド成果物があるなら、変更前後のサイズと中身を比べる

### モバイルアプリ

- エミュレータ・シミュレータで操作し、動画とスクショを撮る
- 対象の OS バージョン・画面サイズを計画に書く

### API

- リクエストと応答をそのまま記録する
- 正常系に加えて、認可（他人のリソース・未ログイン）とバリデーションの異常系を確かめる

### バッチ・定期実行

- 実行前後のデータを件数・カラムの単位で比べる
- 2 回実行しても壊れないか、途中で失敗したときの状態を確かめる

### DB マイグレーション

- スキーマの差分を記録する
- ロールバックできるか、既存データへの影響（NULL・デフォルト値・ロック時間）を確かめる

### ライブラリ・CLI

- 公開しているインターフェースの変更有無を確かめる
- 利用側の使い方で実行して結果を記録する

### CI・インフラ・設定

- ワークフローや設定を実際に動かした結果を記録する
- 変更が効く環境を特定する
